JVM 启动与垃圾回收（GC）调优参数配置指南

汇集从 Java 7 到 Java 25+ 的主流垃圾回收调优参数模板，并附 CMS & ParNew 内存与线程细化配置表。

一、各版本 GC 参数推荐 二、CMS & ParNew 调优参考表 三、配置与使用注意事项

一、各 Java 版本 GC 参数推荐

1. Java 25+（分代 Shenandoah GC）

特性说明：启用 Compact Object Headers（紧凑对象头）与 Generational Shenandoah（分代超低停顿收集器）。

方案 A：极致性能 / 低延迟常驻模式（推荐游戏端 / 固定内存环境）

-XX:+ExplicitGCInvokesConcurrent -XX:ReservedCodeCacheSize=384M -XX:+AlwaysPreTouch -XX:+UseCompactObjectHeaders -XX:+UseShenandoahGC -XX:ShenandoahGCMode=generational -XX:ShenandoahGCHeuristics=adaptive

方案 B：动态内存归还模式（推荐空闲节约内存环境）

-XX:+UnlockExperimentalVMOptions -XX:+ExplicitGCInvokesConcurrent -XX:ReservedCodeCacheSize=384M -XX:+UseCompactObjectHeaders -XX:+UseShenandoahGC -XX:ShenandoahGCMode=generational -XX:ShenandoahGCHeuristics=adaptive -XX:+ShenandoahUncommit -XX:ShenandoahUncommitDelay=30000

2. Java 9+（G1 GC）

特性说明：现代 Java 默认的低停顿垃圾收集器。

方案 A：高响应 / 极致低停顿模式（推荐客户端 / 动作密集场景）

-XX:+ExplicitGCInvokesConcurrent -XX:ReservedCodeCacheSize=384M -XX:+AlwaysPreTouch -XX:+UseG1GC -XX:MaxGCPauseMillis=25 -XX:GCPauseIntervalMillis=50 -XX:+G1UseAdaptiveIHOP -XX:+UseAdaptiveSizePolicy

方案 B：自适应周期回收模式（兼顾性能与周期性内存整理）

-XX:+ExplicitGCInvokesConcurrent -XX:ReservedCodeCacheSize=384M -XX:+UseG1GC -XX:MaxGCPauseMillis=50 -XX:+G1UseAdaptiveIHOP -XX:+UseAdaptiveSizePolicy -XX:G1PeriodicGCInterval=30000 -XX:+G1PeriodicGCInvokesConcurrent

3. Java 8（CMS + ParNew 经典低延迟方案）

-Xmx4096M -Xms4096M -Xmn1024M -XX:+UseConcMarkSweepGC -XX:+UseParNewGC -XX:+ExplicitGCInvokesConcurrent -XX:+AlwaysPreTouch -XX:SurvivorRatio=25 -XX:MaxTenuringThreshold=1 -XX:TargetSurvivorRatio=90 -XX:CMSInitiatingOccupancyFraction=60 -XX:+UseCMSInitiatingOccupancyOnly -XX:+CMSScavengeBeforeRemark -XX:+CMSParallelRemarkEnabled -XX:+CMSConcurrentMTEnabled -XX:+UseCMSCompactAtFullCollection -XX:CMSFullGCsBeforeCompaction=1 -XX:ParallelGCThreads=12 -XX:ConcGCThreads=4 -XX:ReservedCodeCacheSize=384M -XX:+UseCodeCacheFlushing

4. Java 7（CMS + ParNew + 永久代调优）

-Xmx4096M -Xms4096M -Xmn1024M -XX:PermSize=256M -XX:MaxPermSize=512M -XX:+UseConcMarkSweepGC -XX:+UseParNewGC -XX:+CMSClassUnloadingEnabled -XX:+ExplicitGCInvokesConcurrent -XX:+AlwaysPreTouch -XX:SurvivorRatio=25 -XX:MaxTenuringThreshold=1 -XX:TargetSurvivorRatio=90 -XX:CMSInitiatingOccupancyFraction=60 -XX:+UseCMSInitiatingOccupancyOnly -XX:+CMSScavengeBeforeRemark -XX:+CMSParallelRemarkEnabled -XX:+CMSConcurrentMTEnabled -XX:+UseCMSCompactAtFullCollection -XX:CMSFullGCsBeforeCompaction=1 -XX:ParallelGCThreads=12 -XX:ConcGCThreads=4 -XX:ReservedCodeCacheSize=384M -XX:+UseCodeCacheFlushing

二、CMS & ParNew 专有调优参考表

设计说明：与 G1、Shenandoah 能够根据运行状况全自动切分 Region 并动态调整分代比例不同，CMS + ParNew 缺乏自适应分代能力。因此，在使用上述 Java 7 / 8 的 CMS 模板时，必须人工计算并指定合理的 -Xmn（新生代大小）与 GC 线程分配，以平衡 Minor GC 频率、对象晋升速度与并发 CPU 争抢。

表 1：-Xmn 与总堆大小建议（CMS 专享）

根据所分配的总堆（-Xmx / -Xms），按照 1/6 至 1/4 的比例计算出的新生代设定值：

总堆（-Xmx / -Xms） 按 1/6 比例 按 1/4 比例 建议起始值
6G 1G 1.5G 1G ~ 1.5G
4G 683M 1G 768M ~ 1G
3G 512M 768M 512M ~ 768M
2G 341M 512M 384M ~ 512M
1G 170M 256M 256M

表 2：GC 线程数建议（专用于 ParallelGCThreads 与 ConcGCThreads 配比）

CMS 在 STW 阶段（ParNew 复制、CMS Remark）使用并行线程，在后台标记/清除阶段使用并发线程。为防止并发 GC 与游戏/业务主线程发生 CPU 抢占导致掉帧，建议按主机线程数调整：

CPU 线程数 -XX:ParallelGCThreads -XX:ConcGCThreads 说明
8 6 2 为业务线程保留约 2 个核心；并发线程保持默认 2 即可，最多不超过 3。
4 2 1 为业务线程保留约 2 个核心；并发线程保持默认 1。

三、配置与使用注意事项

  1. CMS 参数替换指南：如果你在 Java 7 或 Java 8 中分配的内存不是 4G，请直接查阅 表 1 将 -Xmn 替换为对应档位的建议值；若机器 CPU 为 4 核或 8 线程，请根据 表 2 替换模板中的 -XX:ParallelGCThreads 和 -XX:ConcGCThreads。
  2. Java 7 专属要求：在 Java 7 下运行大型模组或复杂应用时，必须保留 -XX:PermSize、-XX:MaxPermSize 以及 -XX:+CMSClassUnloadingEnabled；迁移至 Java 8 时应将其移除。
  3. 架构寻址：当 -Xmx 超过 1536M 时，必须使用 64 位（x64）JVM 启动。
